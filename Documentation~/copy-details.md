# 操作・コピー範囲・命名の詳細

[基本の使い方](../README.md#使い方) · [困ったときの対処](installation-and-recovery.md)

## 複製画面の操作

### 複製元を選ぶ

HierarchyのアバターかScene名の右クリックから画面を開きます。`Tools > Avatar Fork`からも開けます。

複製元が空なら、Hierarchyのアバターを「Source avatar（複製元）」欄へドラッグしてください。Hierarchyで選択するだけでは、開いている画面の複製元は変わりません。

Scene内に複数の候補がある場合は、「Choose from Scene（Scene内の候補から選ぶ）」でも指定できます。候補外のアバターを直接指定した場合、一覧には「下の複製元欄で指定」と表示します。実際の複製対象は複製元欄で確認してください。

### 名前と保存先を選ぶ

複製名の初期値は`複製元の名前_Copy`です。日本語を含む名前もそのまま使えます。

既定の保存先は`Assets/複製名`です。「Save in（保存する場所）」の「Change…（変更…）」でAssets内の親フォルダーを選ぶと、その中へ複製名のフォルダーを作ります。「Use Assets（Assetsに戻す）」で既定に戻せます。実際の作成先は「Destination（作成先）」に表示します。

- 同名があれば末尾に番号を付け、既存のコピーへ上書きしません。
- Assets外や既存コピーの内側を選ぶと、理由を表示して直前の保存先を維持します。
- フォルダー選択をキャンセルしても、入力や結果は変わりません。
- 完了後は作成済みの場所を表示し、再実行ボタンを隠します。名前・複製元・保存先を変えると、次のコピーを作る画面に戻ります。
- スクリプト再読み込みでは古い完了結果を復元しません。過去に作ったフォルダーを移動・改名する操作ではありません。

### 複製後のScene

複製後は、元アバターと同じSceneのルート末尾にコピーを追加して選択します。開いているSceneと既存オブジェクトの順序は維持し、元Sceneを自動保存しません。別Sceneの出力は、保存済みコピーとしてフォルダー内に残します。

UndoでHierarchyへの追加だけを取り消し、Redoで戻せます。生成済みの素材・Prefab・SceneはUndoで削除しません。ファイルの複製後に追加だけが失敗した場合は、同じ画面の「Add to Hierarchy（Hierarchyへの追加を再試行）」で同じ出力を使って追加できます。

追加済みの個体は、Sceneを保存して開き直した後も個体の識別子で探します。別Sceneへの移動や親の変更後も、同じPrefabを使う別の個体を自動で選びません。配置先のSceneを閉じている場合や個体を削除した場合は、見つからないことを理由に新しく追加しません。配置先のSceneを開き直すか、「Existing copy（既存のコピー）」へ対象を指定して「Use the selected instance（選んだ個体を使う）」を押してください。追加を取り消した後など、新しく配置する場合は「Add a new instance to the source Scene（元Sceneへ新しい個体を追加する）」を使います。

保持していた参照が無効になった場合は、保存済みScene内の個体識別子とPrefabのGUIDが両方一致する個体だけを再取得します。未保存Sceneなどで同一性を確認できない場合は、自動で採用せず手動での指定を求めます。Play Modeへの移行中・実行中・終了中とコンパイル中は、配置・選択・既存個体の再指定を無効にします。Play ModeでSceneを再読み込みした場合は、終了後に実行前の識別子から個体を再取得します。Sceneを再読み込みしない設定では、有効な参照を維持します。配置が例外で失敗した場合は、生成個体の後始末を行い、追加前の追跡状態へ戻します。

作成画面を開いたままコピーを改名した場合も、完了画面の保存先と再配置に使うPrefabを更新します。複製元Sceneのファイル名を変えて閉じ直した場合も、同じSceneを開けば新しい個体を追加できます。

コピーの位置・向き・大きさと、アバター自身の有効・無効を引き継ぎます。元の親が無効でもコピーはSceneのルートに追加するため、アバター自身が有効なら表示されます。親の回転と不均一なスケールによる変形をルートで再現できない場合は、作成前に停止します。

### 表示言語を変える

上部の「Language / 言語」でEnglish・日本語を切り替えられます。初期表示は英語で、選択は同じPCのUnity Editorで保持します。Hierarchyのメニューも選んだ言語になります。

入力済みの名前・保存先・完了結果は切り替えても維持します。Unity本体の表示言語は変更しません。

## コピーするものと共通で使うもの

| 扱い | 対象 |
| --- | --- |
| コピーして参照を分ける | マテリアルと親マテリアル、画像、モデル・メッシュ、アニメーション、Animator Controller、メニュー、パラメーター、各種設定 |
| コピーして参照を分ける | アバターが参照するAssets内のShaderとinclude。コピーごとにShader名を変え、Fallback・UsePassも対応させる |
| 複製元と共通で使う | Unity標準素材、Packages内のSDK・MA・lilToonなど、スクリプト・DLL |

モデルの外部マテリアル対応も引き継ぎます。モデル内部のマテリアルはコピー側で外部ファイルに取り出し、モデルへ割り当てます。

保存されたGUID参照と、設定に保存された素材パスをコピー内のファイルへ付け替えます。コピーには新しいGUIDを割り当てます。Prefabとの接続を解除した現在のHierarchyを保存します。

共通で使うものを変更・更新すると、同じものを使う他のアバターにも影響することがあります。対象は完了画面と`BranchReport.json`に記録します。Shader独自の操作で元のShaderへ再接続される場合があるため、描画設定を変えた後も見た目と参照を確認してください。

## 未保存の変更と停止する条件

名前のあるSceneの未保存変更と、マテリアルなどUnity形式の素材の未保存変更もコピーへ転記します。元のScene・素材を保存し直さず、元ファイルの内容が変わっていないことを処理内で確認します。

保持を確認できない次の条件では、処理を始めません。

- アバター外のSceneオブジェクトへの参照。
- 名前のない未保存Scene。
- 未保存の読み込み済みモデルへの直接変更。
- 未適用のインポート設定。
- バイナリ形式のUnity素材。

独自スクリプトが実行中に名前やパスから探す素材は、一般的な方法で完全に解析できません。検証したパッケージ・ギミック以外は、その動作も確認してください。

元から参照先が存在しないGUIDは、コピー側の参照を空にし、元のGUIDを保持しません。現在のMissing相当の状態を保ち、後から原本の復元で再接続されることを防ぎます。元データを修復する機能ではありません。件数と対象は完了画面と記録で確認できます。

Unityの読み込み後とScene保存後に、素材・meta・親マテリアル・Unityの依存関係を検査します。参照漏れを検出すると失敗として知らせ、出力フォルダーに失敗記録を残します。[複製が失敗した場合](installation-and-recovery.md#複製が失敗した場合)を確認してください。

## ファイルの名前と配置

複製名を`るるね赤`にした場合、アバターのルート名、`るるね赤.unity`、`るるね赤.prefab`、保存フォルダーを同じ名前にします。同名があれば`るるね赤 1`のように採番し、素材も含めて同じ確定名を使います。

| 対象 | 保存名の例 |
| --- | --- |
| マテリアル | `Materials/Purple__るるね赤.mat` |
| モデル内のマテリアル | `Materials/元モデル名_元材質名__るるね赤.mat` |
| 画像 | `Textures/元名__るるね赤.png` |
| Controller | `Controllers/FX__るるね赤.controller` |
| モデル | `Models/元名__るるね赤.fbx` |

アニメーションはAnimations、PrefabはPrefabs、設定はSettings、参照するAssets内のShaderはShadersなどにまとめます。同じ種類に同名の素材がある場合だけ、複製名の前へ短い識別子を加えます。Material・Controller・設定assetの表示名もファイル名に揃えます。

子オブジェクト名・ボーン名・BlendShape名・Animatorのステート名とパラメーター名・Clip内部名・モデル内部の割当識別子は維持します。

### コピーからさらに複製する

再分岐では`BranchReport.json`に記録した元名と識別子を使います。例えば`Purple__るるね赤.mat`から`rurune blue`へ複製すると、`Purple__rurune blue.mat`となり、前の複製名は積み重ねません。元の名前に`__`があっても分割しません。

この記録は素材一式と一緒に保持してください。旧形式のコピーからも新形式へ複製できます。既存コピーを自動改名する機能ではありません。

## Blueprint IDの扱い

複製先のVRChatのBlueprint IDは必ず空にし、新規アバターとしてアップロードする状態にします。複製元の公開アバターの更新先は引き継ぎません。MA・ギミック・見た目の設定は保持します。

保存したPrefabとSceneの両方でIDが空であることを検査し、残っていれば失敗にします。後から複製元のIDを手動で設定すると、独立したアップロード先ではなくなります。

## コピーの名前変更

[基本の操作手順](../README.md#コピーの名前を変える)で、変更内容のプレビューを確認してから実行します。同じ親フォルダーに同名がある場合は停止します。

| 変更するもの | 維持するもの |
| --- | --- |
| アバターのルート・Scene・Prefab・フォルダーの名前、自動で付けた素材名のコピー名部分 | 手で付けた素材のファイル名・表示名、後から追加したファイルの名前 |
| コピー内の素材パス、Shader名とincludeなど | ボーン名・子オブジェクト名・Animatorのステート名やパラメーター名、素材のGUID、既存のBlueprint ID |

新しいコピーを作る操作ではありません。アップロード済みなら、次のアップロードも同じアバターの更新になります。元名と識別子の記録は引き継ぐため、名前変更後の再分岐でも前の複製名を重ねません。

コピーの外にある設定やスクリプトが素材の場所をパスで指定している場合、そのパスは更新しません。複製後にコピー外の素材を追加参照すると、名前変更時の独立性検査で停止します。必要なら新しいコピーを作り、素材をまとめ直してください。

### 名前変更を始められない条件

- 対象のScene・素材・インポート設定に未保存変更がある場合。自動保存や破棄はしません。
- 名前のないSceneが開いている場合。先にSceneへ名前を付けて保存してください。
- シンボリックリンク・ジャンクションを含む保存先、またはそのようなリンクを含むコピー。コピー外の物理ファイルを書き換えないため、変更前に停止します。

### 処理中のSceneと復元

保存済みの対象Sceneは処理中に閉じ、名前変更後に開き直します。開いていたSceneの並び順・読み込み状態・アクティブSceneも維持します。

コピー外の読み込み済みSceneに追加したアバターも、自動で付けた旧名だけを変更します。そのSceneは未保存になるため、確認後に保存してください。手動で付けたルート名は維持します。Prefab接続を解除してコピーを識別できなくなった場合は、Projectでコピーのフォルダーを右クリックして名前変更を開いてください。閉じているコピー外のSceneは書き換えません。

生成したSceneでも親の下や無効な階層に置いた個体を検索し、同じPrefabの個体が複数あれば、旧自動名の個体をそれぞれ改名します。手動名、親や子オブジェクトの名前は維持します。コピー外のSceneに反映した名前の変更はUndo・Redoの対象です。ファイル一式の改名はUndoで戻りません。

Undoで個体の名前だけを旧名へ戻した場合、その後の一括改名では手動名と同じ扱いで維持します。再び自動名に合わせる場合は、個体の名前を現在のコピー名へ戻してから次の一括改名を行ってください。

途中で例外が起きた場合は、元のパスとファイル内容へ戻します。復元用ファイルと移動の記録は、制作プロジェクトの`Library/AvatarFork/Rename/`に保持します。Unityの強制終了などで処理が途切れた場合は自動復元しません。[中断時の復元手順](installation-and-recovery.md#改名の途中でunityが終了した場合)で復元するまで再実行しないでください。
